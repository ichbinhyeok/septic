# Request builder studio direction

Preview: `/design-preview/studio/request-builder/`

Visual thesis: treat the builder as a premium property-research desk, not a government form or a generic SaaS wizard. A full-bleed working-room image establishes the service, then a cardless three-stage workspace moves from property identity to requested artifact to official route.

Content plan:

1. Image-led promise and direct jump to the builder.
2. Property, record and route fields beside a live paper request.
3. A visual explanation of the identifiers and artifacts that make an archive request actionable.
4. Device-local follow-up tracking and a service handoff.

Interaction thesis: inputs update the route, checklist, filename and letter immediately; official-intake confirmation unlocks the sent state; the existing copy, download, print and 30-day local progress behaviors remain intact. Motion is limited to the hero entrance and a subtle paper-settle effect, with reduced-motion support.

Reference mockup: `docs/design/studio/mockups/request-builder-v1.webp`.

The preview reuses the existing request-generation implementation from `app.js` so wording and tracking stay aligned with the public builder. It remains `noindex,nofollow`, and the production route is not switched by this work.
